# MiniClipStudio 全功能实现顺序

制定：2026-11-12。状态：实施建议，不代表各阶段已实现，也不自动批准未确定的GUI/后端/依赖迁移。适用Windows本地桌面产品与目前已明确范围，未来新增需求再放入依赖链。

## 当前起点

已有Win32音频录制、设备枚举、取消/回收、48kHz/S16/stereo WAV链路、命令行实验、资源与状态检查、根VS方案和部分测试。实际源码覆盖录音、媒体探测和基础视频解码/首帧导出，其他目录多为职责说明。2026-11-12用户报告S00验收完成；S01已实现本地探测与GUI/CLI入口并通过自动验证。用户本轮选择先做S02；S02基础CLI视频解码/首帧PNG及顺序帧计数已实现并自动验证，S03基础CLI转码/裁剪已实现并自动验证，具体范围见TRANSCODING.md；S04基础本地音频播放已实现并自动验证，具体见AUDIO_PLAYBACK.md；窗口/听感待人工验收，S05基础1倍速预览/同步/seek已实现，范围见VIDEO_PREVIEW.md，倍速与人工验收待后续；S06基础摄像头/麦克风录制已实现，GUI与长录待验收；S07手动区域无声视频分支已实现；系统声音/窗口跟随等未完成，S08及以后仍后续。范围见VIDEO_FRAME_EXPORT.md。

## S03之后增加岗位实验线（2026-11-13）

功能正确优先，但不等到S17才观察性能。S03已加入API计时/CPU/工作集与预热重复基准；下一步先做用户真实素材验收、Release CPU热点和一个受控实验，再评估Linux headless CLI、有界并发、GPU及一个模型的推理profiling。重大CMake/平台迁移仍先确认方案，不在本轮安装/重写。

主产品S编号不变，岗位实验线按依赖穿插，优先于大规模UI美化/大量AI扩展。S17仍是完整版本集中优化，不是现在盲目优化的许可。事实/限制见PERFORMANCE_WORKFLOW.md，本地岗位对照见local-notes/实习岗位对照与性能优化路线.md。

## 排序原则

1. 每轮一个可验证功能，概念→最小数据流→代码→运行→解释→笔记；不一次交付整个阶段。
2. 先正确功能，后性能优化。线程安全、格式/时间/所有权、有限资源、错误处理属于现在必做的正确性。
3. 沿用现有VS/Win32和FFmpeg C API，不为执行路线图就先更换Qt/CMake或SDK。
4. 优先获得可复用能力：探测→解码→转换/输出→播放→录制扩展→作品/渲染→编辑→高级能力。
5. 记录验收证据，未执行的实验不标通过；学习理解与产品实现分开跟踪。

## 分阶段任务与验收

### S00 收尾现有录音并建立用户能复现的基线

**前置**：现有代码与根VS方案。

**小步顺序**：正常录5—10秒并试听；快速开始/停止、连续重启、录制中关窗；无设备/占用/断开、不可写路径、长时测试逐项记录。对失败项一次修一个原因。录音计时、麦克风电平、暂停恢复列为后续小功能，不和当前回归混做。

**主要目录**：src/application、src/capture/audio、tests/manual。

**阶段验收**：Debug/Release和已有测试继续通过；关键GUI操作有用户记录；不能把驱动阻塞伪装为退出。

**学习重点**：atomic、join、生命周期、错误分层；基础实现及程序化测试已有，2026-11-12用户确认已验收。

### S01 媒体信息探测

**前置**：S00基线。

**小步顺序**：先CLI读取一个文件；再列全部音视频流、编码、采样率/布局、尺寸、帧率、时长与time_base；区分未知时长/多音轨；最后做简单文件选择与信息面板。

**主要目录**：src/media/probe、apps/cli、tests/integration。

**阶段验收**：音频、视频、多流、损坏/缺失文件得到正确结果或可读错误；未知值明确显示未知。

**学习重点**：结构体/vector、借用、容器/流与有理数；不调用ffmpeg CLI代替实现。

### S02 视频解码和单帧导出

**前置**：S01。

**小步顺序**：按实际codec找解码器；读取首帧；处理stride/像素格式；转换可显示格式；保存单图；再顺序解码多帧与尾部排空。音频解码复用现实现，不重写一遍。

**主要目录**：src/media/decode、video、ffmpeg。

**阶段验收**：验证尺寸、颜色/方向、帧数量及内存清理；多种已声明支持样本；不把第一帧显示成功当完整视频解码通过。

**学习重点**：二维内存、行跨度、像素、颜色、packet/frame与send/receive。

### S03 单素材转码和可靠文件导出

**前置**：S01、S02。

**小步顺序**：整理音频转换接口；先视频无声转换，再保留音视频；设置目标尺寸/采样参数；保留或转换轨道；进度、取消、临时输出与收尾；最后精确裁剪一段。

**主要目录**：src/media/encode、mux、audio、video；src/export。

**阶段验收**：重新打开输出验证轨道/格式/时长/时间戳和末尾，试听/观看；取消或写盘失败不报告成功。

**学习重点**：编码与封装、PTS/DTS、time_base、重采样；区分包直通与重编码裁剪，精确裁剪不能默认只复制包。

### S04 音频播放

**前置**：S01及已有音频解码。

**小步顺序**：先播放本地WAV；接入解码和输出设备；暂停/继续、音量、结束；再有界缓冲和取消。不要从第一步就做视频同步。

**主要目录**：src/playback、platform/windows/output、media/audio。

**阶段验收**：正确采样格式、无明显断音/速度变化；暂停停止输出并保留位置，停止/结束/关闭后释放会话；缓冲容量有限。暂停不销毁会话，以保留待播数据。S04已实现窗口/CLI及有界队列，自动/真实设备静音验证通过，听感与GUI待人工验收，见AUDIO_PLAYBACK.md。

**学习重点**：生产者/消费者、mutex/条件等待、音频设备消费速率与时钟。

### S05 单视频预览与音视频同步

2026-11-14：基础1倍速、暂停/seek、真实音频时钟和Win32绘图已实现；倍速留独立小步，具体支持与验证见VIDEO_PREVIEW.md。

**前置**：S02、S04。

**小步顺序**：先显示无声视频，按时间戳调度；加入声音和主时钟；暂停/继续；seek后清理旧解码/队列并拒绝过期结果；倍速最后做。

**主要目录**：src/playback、platform/windows/output、media/video。

**阶段验收**：长短素材都可播放；暂停恢复/seek后无旧帧覆盖，结束收尾正确，音画同步有测量。

**学习重点**：时钟、队列、请求代次、seek/flush；显示帧不是完整播放器。

### S08 素材库与基础编辑界面

**前置**：S01、S02、S05。

**小步顺序**：导入文件并分配稳定素材ID；列表/缩略图/时长；素材预览；音频波形；重复导入/缺失素材反馈。代理、复杂缓存后做。

**主要目录**：src/assets、ui、application。

**阶段验收**：导入不改原素材；同一素材能被多个片段引用；缩略图/波形任务取消和来源关系正确。

**学习重点**：ID与路径区别、派生数据、异步任务。此处如需Qt仅先单独评估，经确认再迁移，不同时换GUI和构建系统。

### S09 作品模型及基础保存/打开

**前置**：S08。

**小步顺序**：定义Project/Sequence/Track/Clip和有理数时间；源入出点/时间轴位置分开；基础序列化版本；先保存打开不带复杂编辑，再验证相对路径和缺失素材重定位。

**主要目录**：src/project、persistence、timeline。

**阶段验收**：重开项目恢复同一素材引用和时间范围；格式版本明确；保存失败不破坏已有作品。

**学习重点**：值对象、稳定ID、序列化、原子保存；项目文件保存描述，不保存AVCodecContext或HWND。

### S10 单轨时间轴求值与统一渲染基础

**前置**：S03、S05、S09。

**小步顺序**：先不做复杂拖拽：给定项目时间求活动片段/源时间；一个片段→两个拼接；以相同模型驱动预览和导出；建立[start,end)边界与舍入测试。

**主要目录**：src/timeline、render、playback、export。

**阶段验收**：片段切点与导出边界准确，预览/输出语义一致；帧率和采样率换算可验证。

**学习重点**：时间映射、确定性求值；文件播放器后端在此适配时间轴，不复制另一套编辑算法。

### S11 基础时间轴编辑与撤销重做

**前置**：S08—S10。

**小步顺序**：选择/移动/裁剪/分割/删除；缩放、播放头和吸附；每项操作通过编辑命令进入；同步实现撤销/重做，保存打开与导出回归。

**主要目录**：src/ui、application、timeline、project。

**阶段验收**：用户能导入两段素材、分割拼接、撤销、保存重开、预览并导出一致作品。

**学习重点**：命令、状态变化、边界不变量；非破坏性编辑，不能为分割直接重写原素材。

### S12 多轨、合成与混音

**前置**：S11。

**小步顺序**：多视频/图片轨道及叠加顺序；位置/缩放/裁切/旋转；多音轨、静音、独奏、增益与淡入淡出；再画中画、变速及声音速度策略。

**主要目录**：src/render、effects、media/audio、video、timeline。

**学习重点**：图层合成、alpha、声道混音、参数与时间关系；增益叠加要考虑溢出/削波。

### S13 常用效果、文字、字幕与关键帧

**前置**：S02、S10—S13；模型/素材条件另核对。

**小步顺序**：先引擎/模型清单和静态图像实验；再单视频离线处理和取消；从视觉检测/分割到背景模糊/抠像、区域染色，再发型形状生成与授权素材面部效果；最后视频时序一致性、预览/导出集成。自动字幕/降噪可作为音频独立分支。

**主要目录**：src/ai/runtime、vision、effects、policies；render。

**阶段验收**：模型来源/版本明确；目标素材效果验收、帧序/同步/内存边界正确；失败可取消；不把单图成功称完整视频AI功能。

**学习重点**：张量/预处理/输出映射、模型推理和时序；FFmpeg读写不替代模型，染发不等于换发型。未选择具体库或下载权重。

### S17 已验收版本的性能优化

**前置**：对应版本功能已正确并冻结验收范围。

**小步顺序**：先Release测CPU/内存/延迟/导出耗时；再按热点做帧包复用、缓存/代理、解码复用；确有收益才考虑并发、硬件编解码和GPU合成。

**主要目录**：tests/performance及实际热点模块。

**阶段验收**：同样输入/硬件/配置下有前后数据，质量/同步/取消/稳定性回归不退化。

**学习重点**：测量、复杂度和资源预算。不是必须等所有未来AI/云功能做完才优化，针对一个已经完整的版本进行。

### S18 商业发行与维护流程

**前置**：S15、该版本必要功能与质量门槛；性能目标按产品要求。

**小步顺序**：干净机器部署/安装/升级/回滚、依赖和符号记录、错误诊断与数据策略、用户文档；核对FFmpeg实际构建/第三方/模型/素材和发行方式；版本回归与发布说明。

**主要目录**：packaging、third_party、docs、build-config。

**阶段验收**：可重复构建/部署、支持矩阵和回归报告明确、发行审查完成，不靠开发机PATH碰巧成功。

**学习重点**：可交付性和版本维护；依赖选型时就检查条件，此处做最终发行复核，不把风险全部拖到最后。

## 每个阶段仍要拆成单次任务

例如S01不一次生成探测框架，依次只做：打开固定文件并读信息 → 列音频流 → 列视频流 → 明确未知参数 → 可读失败 → 用户选文件 → 测试与教学。类/文件仅因实际职责引入，不为了目录存在写空壳。

一个阶段进入下一阶段前：能亲自在VS生成；正常/失败/取消行为有对应实验；相关字段与所有权能解释；笔记更新。某个异常需要用户硬件配合时记录限制，只能在风险与范围明确后推进独立任务，不能装作全部通过。

## 可交付版本的分界

- V1基础编辑闭环：S01—S05、S08—S11，得到导入、预览、剪辑、保存、导出；S06加入则有摄像头录制，S07可延后。

- 商业发行：对选定版本执行S17必要性能工作和S18，不把“开发功能闭环”直接称商业发行合格。
