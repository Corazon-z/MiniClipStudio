# MiniClipStudio 目录与模块总体规划

日期：2026-11-07。状态：架构草案，等待确认后分阶段落地。

## 1. 产品目标与当前事实

将用户提到的“clipcharm”暂按 Clipchamp 理解，作为录制与编辑体验的方向参考。本文是 MiniClipStudio 的产品规划，不是对参考产品当前功能的调查或完整复制承诺。

默认范围：Windows 本地桌面音视频录制与编辑软件，核心媒体处理使用 FFmpeg C API；优先本地文件、本地项目和离线导出。账号、云同步、多人协作、素材商城和 AI 服务列为可选扩展，不属于首个可用版本。

已确认的现状：
- 已有 `AudioCapture/AudioCapture.slnx` 和一个 VS C++ 工程；C++20、v145，x64 配置显式连接本地 FFmpeg SDK。
- 已有 Win32 按钮与工作线程，能读取 DirectShow 音频包并打印大小；可靠停止和 WAV 保存尚未实现。
- `legacy/win32_audio_capture/` 保存原始代码，不能覆盖。
- 当前不引入 Qt 或 CMake；没有进行任何代码迁移。

待确定：首版具体功能、目标硬件、支持格式与分辨率、屏幕/系统音频捕获后端、GUI 后期选型、项目文件具体格式、第三方依赖与发布条件。以下目录表示职责边界，不表示对应功能已完成。

## 3. 模块职责、输入与输出

| 模块 | 接收 → 产生 | 职责边界 | 引入阶段 |
|---|---|---|---|
| common | 错误码/时间值 → 可读错误/统一时间运算 | 保持小型，不收集所有杂项，不依赖 GUI/FFmpeg | M1 起按需 |
| platform/windows | Windows 请求/回调 → 设备信息、采集数据或播放输出 | 处理系统句柄和平台后端，不保存项目编辑逻辑 | M1–M4 |
| media/ffmpeg | FFmpeg 对象/错误 → 安全资源管理与诊断 | 逐步封装所有权，不隐藏关键参数与错误 | M1 |
| probe | 输入路径 → 编码、时长、流和格式信息 | 不创建编辑片段，不负责素材面板 | M1–M2 |
| demux | 输入会话 → AVPacket | 打开、读取、seek、取消、关闭；处理流选择 | M1–M2 |
| decode | AVPacket → AVFrame | send/receive、缓冲排空与格式变化 | M1–M2 |
| audio | 音频帧 → 转换/混音后的音频帧 | 重采样和布局转换，后期多轨混音；不操作按钮 | M1–M3 |
| video | 视频帧 → 指定像素/尺寸/颜色帧 | 明确 stride、颜色范围与格式；不管理时间轴 | M2–M3 |
| encode | 目标帧与配置 → 编码包 | 编码参数、能力检查、延迟和排空 | M1–M3 |
| mux | 编码包 → 媒体文件 | header、时间基转换、写包、trailer 和 IO 错误 | M1 |
| capture | 设备选择与录制配置 → 录制结果/状态/错误 | 编排捕获后端、同步、编码与封装；不直接控制窗口 | M1，视频扩展于M3 |
| assets | 导入路径 → 稳定素材ID和派生数据任务 | 元数据、离线素材重定位、缩略图与波形缓存 | M2–M5 |
| project | 编辑命令 → 可序列化的项目状态 | 描述用户作品，不保存活动解码器和GPU句柄 | M5 |
| timeline | 项目时间与片段 → 源媒体时间/活动片段 | 分割、裁剪、移动、吸附、轨道重叠规则 | M5 |
| effects | 帧/参数/时间 → 处理后的帧或音频块 | 初期基础效果，后期关键帧和转场；按需采用libavfilter | M3–M5 |
| render | 项目快照与时间 → 合成视频帧/混音音频块 | 解析时间轴、解码源素材、执行效果和合成 | M5 |
| playback | 播放命令 → 实时预览与播放状态 | 时钟、音视频同步、缓冲、seek；使用render的编辑语义 | M4–M5 |
| export | 项目快照与导出配置 → 输出文件/进度/结果 | 非实时调度render、encode、mux；不自行复制一套编辑算法 | M3–M5 |
| application | UI命令 → 启动任务/项目修改/结果通知 | 编排录制、导入、编辑、保存、导出及撤销重做 | M3–M5 |
| persistence | 项目状态 ↔ 项目文件 | schema版本、原子保存、迁移、自动保存、恢复 | M5 |
| ui/apps | 用户输入/任务结果 → 界面状态和命令 | 窗口生命周期、显示与交互，不直接长期执行媒体操作 | 现有Win32起步 |

屏幕、系统声音和摄像头不强制使用同一种捕获后端。DirectShow 音频输入沿用现有方案；未来捕获后端需先调查本机能力并做小实验。平台 API 可负责获取原始数据，核心解码、转换、编码、封装继续使用 FFmpeg C API。

## 4. 依赖规则与数据流

```text
UI / 程序入口
        ↓
application（用例与命令）
        ├→ capture → 平台捕获/媒体输入 → decode → audio/video → encode → mux
        ├→ assets → probe / 后台派生数据
        ├→ project + timeline + persistence
        ├→ playback → render → timeline + effects + media
        └→ export   → render → encode → mux

各层按需使用 common；Windows 专用代码集中在 platform/windows。
```

- 媒体底层不能引用窗口 HWND 或时间轴控件；GUI 不能成为解码器退出所必需的资源所有者。
- `project` 保存作品数据，`timeline` 解释这些数据在时间上的含义；二者不依赖 UI。
- `render` 不依赖 playback/export；调用者决定实时还是离线、输出质量和取消策略。
- `persistence` 依赖项目模型，项目模型不主动访问磁盘，避免循环依赖。
- UI 发送命令，后台返回状态/进度/错误；按消息或明确队列通信，不让工作线程直接操作控件。

### 核心数据模型（概念，尚未生成类）

| 概念 | 保存内容 | 不保存内容 |
|---|---|---|
| MediaAsset | 稳定ID、媒体定位、原始参数、派生数据关联 | 当前解码器指针 |
| Project | schema版本、素材清单、序列、项目设置 | 活动线程句柄 |
| Sequence | 画布大小、帧率有理数、音频目标、轨道顺序 | 窗口控件状态 |
| Track | 类型、顺序、片段、静音/可见等属性 | 正在运行的编码上下文 |
| Clip | 素材ID、源入点/出点、时间轴位置、速度、效果引用 | 原媒体数据的完整复制 |
| Effect/Transition | 类型、参数、关键帧和有效时间 | 未定义所有权的裸指针 |
| RenderRequest | 项目快照/版本、请求时间、目标输出规格 | 对正在变化的UI状态的借用 |
| ExportJob | 项目快照、配置、进度、取消状态、输出结果 | 可被编辑线程随意更改的项目引用 |

非破坏性编辑指“记录如何使用素材”，例如一个片段引用原素材第2–5秒；分割片段通常只改项目描述，不立即改写原文件。

时间范围统一采用起点包含、终点不包含 `[start, end)`；源时间与项目时间分开，帧率用有理数表示。先实现正常速度，再扩展变速映射。精确边界、舍入策略和可变帧率处理需另写规格和实验，不能用浮点秒随意比较。

## 5. 线程、生命周期与失败处理

初期录音只需要 GUI 线程与一个采集工作线程。目录数量不代表线程数量，后续用性能证据决定并发。

- 会话状态：空闲 → 启动中 → 运行中 → 停止中 → 完成/失败；取消请求不能被后续初始化覆盖。
- 资源由明确的会话/任务拥有；包、帧、输入输出上下文、重采样器、系统句柄逐项配对清理。
- 阻塞读取的取消必须验证后端行为；`std::atomic` 只解决共享标志访问，不自动唤醒系统调用。
- 只有真正退出后才释放线程管理资源并允许重启；不把超时解释为线程结束。
- 引入队列时必须有容量、背压、结束和错误约定。离线导出不能因队列满随意丢帧；实时预览的丢帧策略要明确记录。
- seek 后旧请求结果不得覆盖新画面，可用请求代次识别并丢弃过期结果。
- 导出基于一致项目快照；用户继续编辑不能使导出过程读取到混杂版本。
- 错误带阶段、FFmpeg文本、输入或设备上下文；用户取消和真实失败分开报告。
- 输出写入失败或取消时不标记为成功；临时文件、最终重命名和残留清理策略须经实验确定。

预览以播放时钟调度并允许按策略降低代理质量；导出按完整时间序列生成，不按UI刷新率跳过内容。二者共享时间映射和效果语义，质量参数可不同。

## 7. 测试、性能与交付规划

- 纯逻辑测试：时间映射、裁剪边界、编辑撤销、项目版本读写；避免测试仅重复实现细节。
- 媒体链路测试：确定性小样本验证采样率/声道/样本数、时间戳、尾部排空及文件可重新读取；视频检查帧数和边界。
- 人工设备测试：无设备、设备忙、断开、快速启停、窗口关闭与试听。明确哪些无法自动化。
- 性能基线：Release配置、硬件、媒体参数、CPU、峰值内存、队列上限、seek/停止延迟、导出耗时；数值目标在获得基线后确定。
- 优化顺序：限频逐包日志 → 缓冲复用 → 有界缓存 → 代理与缩略图 → 根据热点考虑并行或硬件加速。每次保持输入一致并验证质量。
- 项目缓存独立于原素材和项目描述，允许删除后重建；缓存键应随素材身份、参数和算法版本变化。
- 当前`.gitignore`全局忽略多种媒体扩展；以后添加可分发测试样本时，必须显式调整规则并确认来源、体积和许可。本次不添加媒体样本。
- 不提交SDK二进制、用户录制、构建输出、密钥或本地笔记。依赖版本和获取/部署说明可进入仓库。
- 商业发布前需核查实际FFmpeg构建及第三方组件、安装升级、用户数据与日志处理；具体许可证判断另行基于当时的官方信息审查。不能由本规划推导已满足发布条件。

理解检查题：
1. project、timeline与render各自负责什么？为什么项目文件不保存AVCodecContext指针？
2. 预览与导出为什么应共享时间映射和效果语义？它们的调度有什么不同？
3. 为什么建立一个capture目录不代表必须创建一个Capture类、一个DLL和一个线程？
